## 1. 产品定位

一句话：**用手机摄像头，把用户变成"看得见自己身体"的人——先诊断体态，再给针对性训练计划，练的时候实时纠错、自动计数、生成可对比的成长报告。**

核心逻辑分层：

| 层 | 回答的问题 | 技术 |
| --- | --- | --- |
| Pose 模型 | 身体在哪里 | MediaPipe / Apple Vision |
| 规则引擎 | 动作对不对 / 体态偏没偏 | Feature Engine + Rule Engine |
| 计划引擎 | 该练什么 | 体态失衡映射 + 动作模板 |
| LLM Coach | 怎么告诉用户 | 生成建议/报告话术 |

**三分离原则**：Pose 找身体、规则判对错、LLM 说话。三个东西不要混在一起。

## 2. 核心技术原理：视频人体姿态估计

### 2.1 原理

- 一帧视频 → 人体姿态模型 → 人体关键点（头/肩/肘/腕/髋/膝/踝等，MediaPipe 为 33 点）
- 每个点输出 `(x, y, confidence)`，如右肩 = (312, 428, 0.98)
- 按骨架拓扑连接关键点并绘制（肩→肘→腕、髋→膝→踝）

### 2.2 角度计算

三点夹角（如肩→肘→腕）：

```
A = 肩, B = 肘, C = 腕
向量 BA = A - B, 向量 BC = C - B
angle = arccos( dot(BA, BC) / (|BA| × |BC|) )
```

### 2.3 规则判断

- 规则示例："过肩" = 手腕 Y < 肩膀 Y（图像坐标 Y 向下）
- 专业判断需综合：手腕位置、肘角、肩部旋转、躯干倾斜、髋部旋转、动作速度、动作顺序

### 2.4 模型选型

| 方案 | 适用 | 特点 |
| --- | --- | --- |
| Apple Vision Framework | iOS 原生 | VNDetectHumanBodyPoseRequest，性能好，SwiftUI 集成方便 |
| MediaPipe Pose | 跨平台 | 成熟、社区大 |
| MoveNet | 轻量 | 移动端快 |

### 2.5 护城河认知

画黄点不难，**难的是从"人体关键点"变成"专业动作/体态评价"**。产品真正的壁垒是规则引擎与知识映射（动作规则库、体态失衡库），且适合 Skill 化：把"羽毛球高远球分析""深蹲分析"等做成独立分析 Skill，底层共用 Pose Engine。

## 4. 模块一：动作分析（动态）

### 4.1 MVP 只做 5 个动作

| 动作 | 能分析什么 |
| --- | --- |
| 深蹲 | 膝角、髋、躯干、深度 |
| 俯卧撑 | 肘角、身体直线、胸部高度 |
| 开合跳 | 手脚同步、次数、节奏 |
| 弓步 | 膝、髋、左右稳定 |
| 平板支撑 | 髋部高度、躯干稳定 |

优先：深蹲 + 俯卧撑。

### 4.2 自动计数（动作状态机）

膝角变化（178°→150°→120°→92°→100°→150°→178°）识别 站立→下蹲→最低点→起身→站立，即一次完整动作。

### 4.3 动作正确性 = 多维判断

不能只看一个角度：
- 膝角 < 100° 判断深度
- 躯干倾斜角（肩→髋）15°/25° ✓，38° ⚠
- 膝盖轨迹 vs 脚尖（内扣检测）
- 髋部轨迹（偏移/不对称）
- 动作速度节奏（下蹲 1.2s / 底部 0.1s / 起身 0.5s，下蹲快+起身快 → 提示）

### 4.4 动作评分卡

```
深蹲动作分析  总评分 86
深度          92  ✓
躯干稳定      84  ✓
膝盖轨迹      76  ⚠
左右平衡      91  ✓
动作节奏      88  ✓
完成次数      12  有效 10
```

### 4.5 实时纠错（最大产品价值）

第 2 次膝盖内扣 → 屏幕提示"⚠️ 注意膝盖不要向内夹"；第 3 次躯干前倾 → "⚠️ 保持胸口抬起"。这就从"视频分析工具"升级为"AI 私教"。

### 4.6 自动训练编排

用户说"我要练胸" → 自动生成今日训练（俯卧撑 3×12 / 宽距 3×10 / 窄距 3×8 / 平板 3×40s）→ 开始训练 → 摄像头识别 → 自动计数 → 判断质量 → 自动休息计时 → 下一组。用户不用碰手机。

### 4.7 动作数字指纹（进阶）

每次动作记录曲线：膝角 / 髋角 / 躯干角 / 重心 / 速度 / 左右差异。连续训练后可输出"过去 30 天深蹲动作质量 71 → 89 分""右侧稳定性明显提高"，产品升级为 **AI 动作成长系统**。

## 5. 模块二：肌肉发力识别（进阶）

### 5.1 技术边界（必须明确）

- 单靠摄像头**不能测"肌肉有没有发力"**——摄像头看到动作结果，EMG 才能看到肌肉电活动
- 表面肌电（sEMG）受肌肉长度、收缩速度、电极位置、协同/拮抗肌影响，**不能简单理解成"EMG 越高 = 越用力"**
- 产品定位："视觉动作 + 生物力学 + 肌电"三层融合，输出推断而非断言

### 5.2 发力对错的 4 种情况

| 情况 | 表现 | AI 反馈 |
| --- | --- | --- |
| A 动作✓ 胸肌充分 | 理想 | — |
| B 动作✓ 胸肌参与不足 | 推力由三头/前束完成 | "动作轨迹基本正确，但推力主要由三头和肩前束完成" |
| C 动作不标准但目标肌群激活高 | 稳定性不足 | "目标肌群在工作，但动作稳定性不足" |
| D 用户感觉强但激活未必高 | 泵感 ≠ 激活 | "主观感受与动作/肌电信号不完全一致"（不直接说"你感觉错了"） |

### 5.3 Muscle Map（肌肉发力地图）

核心概念升级：不叫"动作纠错"，叫"给身体装调试器"——屏幕上显示不同肌群的参与度：

```
目标肌群 ████████░░ 82%
辅助肌群 ██████░░░░ 61%
代偿肌群 ████████░░ 78% ⚠️
→ 建议：降低重量、收紧肩胛、调整肘部轨迹
```

### 5.4 分层落地（避免吓跑用户）

- **Level 1 纯摄像头**：Pose → Biomechanics → 目标肌群参与概率（"推断"，如胸肌参与概率 78%，不能写成"检测到胸肌 78% 发力"）
- **Level 2 摄像头 + 少量 EMG**（最推荐）：只测 3 块肌（如卧推的胸肌 + 前束 + 三头），佩戴 3 个传感器，建立个人模型

### 5.5 个人校准

不同人动作完全不同（A：胸 80%/三头 40%/肩 30%；B：胸 55%/三头 80%/肩 60%）。先让用户做"发力校准"（单独收缩胸肌 10s、单独屈肘 10s）建立个人 EMG baseline，再做正式动作。不能简单说 B 动作一定错误。

### 5.6 目标肌群匹配度

选"今日练胸"，系统按肌肉匹配度推荐：上斜卧推 92% / 夹胸 96% / 卧推 87% / 俯卧撑 74%。结合个人数据："你做卧推胸肌参与 72%，但夹胸 94%，建议卧推降重 10% 重建胸肌主导推力"——开始有教练感。

### 5.7 代偿识别（商业价值最高）

- 二头弯举：肱二头肌低 + 前三角/斜方肌高 + 身体摆动 → "你不是举不起来，是在用身体借力"
- 侧平举：三角肌中束低 + 斜方肌上束高 → "重量偏大，在用斜方肌代偿"

### 5.8 疲劳识别

第 1 组（质量 92 / 代偿 12）→ 第 3 组（87/25）→ 第 5 组（71/47）→ "你不是意志力不够，是动作质量明显下降，建议停止当前组"。注意：EMG 疲劳指标需结合动作/信号特征判断，不能单一指标直接等同疲劳。

### 5.9 四模型架构

| 模型 | 回答 |
| --- | --- |
| ① Pose Model | 你怎么动（关节/角度/轨迹/速度/稳定性） |
| ② Biomechanical Model | 理论上应该谁发力（动作/关节/力矩/肌肉协同） |
| ③ EMG Model | 实际激活了谁 |
| ④ Coach Agent | 该怎么调（检测→推理→建议→重新测试） |

### 5.10 数据资产

核心数据库不是"1000 个健身动作"，而是：**动作 × 人体 × 肌肉 × 负荷 × 肌电 × 动作质量 × 训练结果** → "什么样的人，用什么动作、什么重量、什么轨迹，能最有效刺激目标肌群"。最终做成可解释的 **Muscle Intelligence Engine**。

### 5.11 MVP 建议（第一阶段只做胸）

卧推/哑铃卧推/上斜卧推/夹胸/俯卧撑 + 胸大肌、三角肌前束、肱三头肌：① 识别动作 → ② 自动计数 → ③ 判断质量 → ④ EMG 测三块肌 → ⑤ 建立个人发力模型 → ⑥ 目标肌群参与度 → ⑦ 找代偿 → ⑧ 实时提示 → ⑨ 训练后总结（"今天胸肌刺激 91 分，前三角代偿下降 18%，有效 27 次，建议下次重量不变"）。

## 6. 模块三：体态分析（Posture Engine）★ 产品第一入口

### 6.1 定位

- **体态是"因"，动作是"果"**：结构偏差会污染动作分析（骨盆前倾者深蹲"看起来躯干前倾"不是动作错误，是结构问题）
- 体态分析先做，反而让动作分析更准
- 为什么适合做第一入口：

| 维度 | 动作分析 | 体态分析 |
| --- | --- | --- |
| 用户门槛 | 换装、做动作 | 拍两张照（正面+侧面） |
| 首次价值感知 | 练完出报告 | 30 秒出诊断报告 |
| 传播性 | 一般 | 强（前后对比图） |
| 与计划的关系 | 计划内执行 | 直接驱动计划生成 |

### 6.2 产品闭环（留存关键：复测对比）

```
体态评估（正+侧两照）
   ↓
诊断报告（问题+严重度）
   ↓
纠正计划（放松+激活+整合）
   ↓
每日跟练（复用动作引擎）
   ↓
复测对比（4-8周角度变化）→ 回到评估
```

4 周后再拍一张，肩线/骨盆角并排对比，数字变化可见——复测对比是留存与付费动机的核心。

### 6.3 技术管线

```
采集：正面照（对称性）+ 侧面照（矢状面）
   ↓
静态特征提取 Posture Feature Engine
（耳-肩偏移 · 肩-髋偏移 · 髋-膝-踝对齐 · 肩线水平差）
   ↓
体态问题规则 Posture Rule Engine
（上交叉 · 下交叉 · 高低肩 · 膝超伸 · X/O型腿 …）
   ↓
肌肉失衡映射（紧张→放松 / 无力→激活）
   ↓
针对性纠正训练计划（放松2+激活2+整合1 · 每天10-15分钟）
```

- 复用同一个 Pose 模型（33 点），不新增模型
- 差异：动作分析取"动态时序"，体态分析取"静态对齐"
- **单目无深度**：偏移量需归一化为比例（如耳-肩偏移 ÷ 躯干长度），不能直接量像素

### 6.4 静态特征测量表

| 视角 | 关键特征 | 计算方式 | 指向问题 |
| --- | --- | --- | --- |
| 侧面 | 耳-肩水平偏移 | 耳垂与肩峰水平距离 ÷ 躯干长度 | 头前引 |
| 侧面 | 肩-髋水平偏移 | 肩峰与髂嵴水平距离（归一化） | 圆肩/驼背 |

| 正面 | 膝间距/踝间距 | 膝、踝水平偏移差 | X/O 型腿 |

### 6.7 分级联动规则

| 分级 | 报告颜色 | 训练计划 | 附加动作 |
| --- | --- | --- | --- |
| 轻度 | 黄 | 每日 1 组纠正（10–15 分钟） | 日常姿势提醒 |
| 中度 | 橙 | 每日 1 组 + 拉伸时长加倍 | 每周 2 次泡沫轴放松 |
| 重度 | 红 | 仅低风险放松动作 | 明确提示就医/物理治疗评估 |

总分算法：100 起步，轻度扣 8 / 中度扣 15 / 重度扣 25，叠加后下限 30，四舍五入取整。

### 6.8 计划生成逻辑（Plan Engine）

1. 模板组合：每问题 = 放松 2 + 激活 2 + 整合 1，每天 10–15 分钟
2. 严重度分级：轻/中/重 → 计划强度联动（见 6.7）
3. 多问题排序（地基顺序）：**骨盆 → 胸椎 → 肩颈**（先下肢基础，再上肢）
4. 复测节奏：4 周首测、8 周对比，输出角度变化曲线

### 6.9 报告 UI 结构（手机端）

自上而下：
1. 顶部导航：返回 / 标题「体态报告」/ 复测
2. **Hero 区**：总分环（体态健康分）+ 风险等级 + 问题数 + 较上次分差
3. **关键指标卡 ×2**：最严重的两个问题实测值 + 分级（如 EAR 0.31 中度）
4. **问题清单**（按严重度排序）：卡片 = 问题名 + 实测值 + 严重度标签，展开显示「紧张→放松 / 无力→激活 / 动作」
5. **CTA**：生成 2 周纠正计划（全宽主按钮）
6. **复测行**：下次复测倒计时 + 对比上次报告入口

设计决策：总分 + 热区图负责"一眼看懂"，卡片负责"钻细节"，底部 CTA 直接衔接计划生成——评估到开练一次点击。

### 6.10 拍照引导（构图参考 + 放松协议）★ 准确性的前提

**核心原则（重要修正）**：**绝不引导用户"对齐"理想姿势**。用户一旦刻意对齐剪影，会下意识挺直背、收下巴、摆正肩膀，测出来的是"被纠正的姿势"，真实体态（圆肩/头前引/骨盆前倾）被掩盖，评估失效。引导只做**构图标准化**，绝不做**体态标准化**。

**构图引导**（只保证照片可用）：
- 安全取景框 + 淡剪影仅作站立区域参考（身体完整入框、居中、距离合适）
- 界面明确标注"取景参考 · 无需贴合"
- 粗粒度位置提示（不影响体态）："身体不完整，请后退" / "请居中站立"

**放松协议（关键）**：
1. 先引导用户活动放松：耸耸肩、摆摆臂（卸下"要摆姿势"的心理）
2. 自然站立指令："像平时一样站，不要挺直，不要收下巴"
3. 系统检测骨骼点稳定（波动 < 阈值，持续 ~1.5 秒）→ 自动抓拍

**多帧选帧**：连拍 2-3 秒，自动选取"骨骼点波动最小"的一帧作为最放松/最自然帧（用户刚站定时可能还在摆姿势，几秒后自然放松）。

**抓拍判定（修订）**：
1. 33 个关键点全部可见（confidence > 阈值）
2. 身体完整进入安全框（构图，非贴合）
3. 骨骼点稳定波动小（放松信号）
不再要求贴合剪影。

**可比性来源（修订）**：复测可比性靠**采集协议一致**（同样指令、同样流程、同样选帧逻辑），而非姿势像素级对齐。专业体态评估本身就是标准化指令 + 自然站立拍摄。

**话术规范**：禁用"对齐 / 贴合 / 对准轮廓"；使用"放松 / 自然 / 像平时一样 / 系统自动拍摄"。

**异常处理**：
- 光线不足 / 背景复杂 → 提示调整环境
- 部分身体出画 → 提示"身体不完整，请后退"
- 宽松衣物遮挡 → 提示"建议穿贴身衣物"
- 检测到刻意姿势（耸肩、过度挺直等）→ 提示"请放松，不需要摆姿势"
